# ShardScope commit skill

Generated by `tools/bootstrap_commit_skill.py`. This file is git-ignored by
policy (PRD section 12.3 ignores all Markdown); regenerate it after cloning
with:

    python tools/bootstrap_commit_skill.py

Reference convention source: @@REFERENCE_STATUS@@

## Preconditions

1. `.shardscope-commit-auth.json` exists with `authorized: true` and the
   student's verified name/email. An agent may set `authorized: true` only
   on the student's explicit, recorded authorization for this repository --
   never on its own initiative and never inferred from silence.
2. `git config --local user.name` / `user.email` match that identity.
3. Tests pass. The helper runs them; do not bypass with `--skip-tests`.

## Procedure

Always go through the helper rather than raw git:

    python tools/commit_safe.py --message "<type>: <description>" --dry-run
    python tools/commit_safe.py --message "<type>: <description>"

The helper stages only allowlisted paths, re-reads
`git diff --cached --name-only`, runs `git diff --check --cached`, and aborts
on anything unexpected.

Commit message format (`<type>: <description>`), types: feat, fix, refactor,
docs, test, chore, perf, ci.

## Hard limits

- Never `git push`, `merge`, `rebase`, `amend`, `--force`, `remote set-url`,
  or open a PR. Each of those needs separate, explicit approval.
- Never `git add -A`, `git add .`, or `git add -f`.
- Never commit: Markdown of any kind, `planning/`, PRDs, trace exports,
  datasets, secrets, the auth file, or anything under `.agents/`.
- Never commit GPU-path changes (see `gpu_review_required` in the auth file)
  until the student says they have finished and approved that change. Pass
  `--gpu-reviewed` only after that sign-off, and never describe
  agent-written GPU code as the student's own work.
- If tests fail, report the failure. Do not commit, and do not edit tests to
  make them pass.

## After committing

Report the short SHA, the author line, and the staged file list. State
explicitly that nothing was pushed.
